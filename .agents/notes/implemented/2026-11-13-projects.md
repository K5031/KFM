# Agent Note: Projects

Status: implemented — a project is an organisation of named fleets, and the window's main screen is its chart

Part of [Standing teams](../proposed/2026-11-12-standing-teams.md). Built on it:
[drafting a project](2026-11-13-drafting-a-project.md). Proposed:
[editing the tree](../proposed/2026-11-13-editing-the-tree.md).

## Problem

A fleet stood alone: one box to type a task into, its own folder and limit, one at a
time in the window. That is the shape of a task doer. What KFM is for is the work of a
human organisation, and an organisation is several teams that exist side by side, each
with a name and a job ("marketing", "dev", "HR", "art"), not a list of past jobs.

The window also showed nothing of a fleet's shape until one was opened, and its size was
a number in a settings file (`max_units`). The user asked what size a fleet has and found
no answer on screen (2026-11-13).

## Decision

**A project is an organisation of fleets** (the user, 2026-11-13): a company, in effect.
It has a name and a folder the person chooses for it (`project.py`). Each of its fleets
has a name and what it is there to do, and is a tree with its K5 lead on top, growing
down as far as K1.

**The person is the top.** Each fleet's lead reports to the person. Fleets do not talk to
each other (the user, 2026-11-13: none for now, to keep it simple); what one needs from
another, the person carries across.

**The chart is the main screen** (`chart.py`). Opening a project shows its fleets side by
side, each drawn as its tree: the fleet's name and state over its K5, then a row for each
rank, so that the same rank lines up across fleets. An agent shows its name, rank, state
and spending. A fleet's size is what the chart shows; the window has no setting for it.
Clicking a fleet's name opens the fleet's timeline, clicking an agent opens it on what
concerns that agent, and the arrow in the bar leads back.

**Projects are switched in the sidebar.** The window opens on the newest.

**A fleet is added on the chart**: its name, what it does (a duty by default, or a task)
and its limit. It works in the project's folder unless another is chosen for it.

**Several fleets run at once**, those of other projects included. Each has its own
`Manager`, record, log and limit; the manager knows nothing of projects. In the window
each fleet is a `FleetView` that holds its manager and its timeline.

```
~/.kfm/projects/<when made>/project.json     name, folder
~/.kfm/projects/<when made>/fleets/<when>/   a fleet's folder; fleet.json has its name
```

`max_units` stays in `fleet.toml` as a guard against a lead that hires without end; it is
not how a person sizes a fleet.

## Alternatives considered

- **A field for the largest number of agents on the start screen.** What was offered
  first. It answers "how large may it get" with a number and shows nothing of the fleet;
  the person still cannot see what they have.
- **One fleet whose K5 runs the company, with the departments under it.** Needs nothing
  new. But the person is then one agent away from every department, each instruction and
  report passes through a lead that costs a request and loses detail, one limit covers
  everything, and a department cannot be stopped or resumed by itself.
- **Fleets that message each other.** Closer to a company, and deferred: every message
  wakes an agent and costs a request, two agents with an open channel keep answering each
  other, and a lead with requests from its peers has two masters. If carrying things
  across becomes the person's chore, the first step is notes one fleet publishes and
  another reads ([shared team memory](../proposed/2026-11-12-shared-team-memory.md)),
  then one question with one answer, as an agent asks its supervisor.

## Consequences

- Several fleets running at once multiply what one costs, and each idle lead still checks
  in. The chart's bar shows how many run and what the project has spent.
- Fleets in one folder can change each other's files; nothing but the person's
  instructions keeps them apart.
- A fleet's tree is drawn in full: one of dozens of agents makes the chart scroll far.
- The window runs the fleets: closing it stops every one, of every project.
- `kfm run` starts a fleet outside any project (`~/.kfm/fleets`), which the window does
  not show; `kfm resume --fleet` and `kfm status --fleet` take a project's fleet by its
  folder.
- Checked in the window's tests on the second harness and in rendered pictures. Not
  checked: on a real display, and with a real model.
