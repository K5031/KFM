# Agent Note: Projects

Status: proposed — a project is an organisation of named fleets, and the window's main screen is its chart

Part of [Standing teams](2026-11-12-standing-teams.md).

## Problem

A fleet stands alone: one box to type a task into, its own folder and limit, one at a
time in the window. That is the shape of a task doer. What KFM is for is the work of a
human organisation, and an organisation is several teams that exist side by side, each
with a name and a job ("marketing", "dev", "HR", "art"), not a list of past jobs.

The window also shows nothing of a fleet's shape until one is opened, and its size is a
number in a settings file (`max_units`). The user asked what size a fleet has and found
no answer on screen (2026-11-13).

## Proposal

**A project is an organisation of fleets** (the user, 2026-11-13): a company, in effect.
It has a name and a folder the person chooses for it. Each of its fleets has a name and
what it is there to do, and is a tree with its K5 lead on top, growing down as far as K1.

**The person is the top.** Each fleet's lead reports to the person. Fleets do not talk to
each other (the user, 2026-11-13: none for now, to keep it simple); what one needs from
another, the person carries across.

**The chart is the main screen.** Opening a project shows its fleets side by side, each
drawn as its tree: the fleet's name over its K5, then a row for each rank, so that the
same rank lines up across fleets. An agent shows its name, rank, state and spending. A
fleet's size is what the chart shows; the window has no setting for it. Clicking a fleet
or an agent opens the timeline the window has today, for that fleet or that agent.

**Projects are switched in the sidebar**, where earlier fleets are listed today.

**A fleet is added on the chart**: its name, what it does (a task or a duty, as now) and
its limit. It works in the project's folder unless it is given its own.

**Several fleets run at once.** Each keeps its own `Manager`, record, log and limit, as a
fleet has today; the manager knows nothing of projects. A project is where its fleets are
kept and how the window groups them:

```
~/.kfm/projects/<project>/project.json     name, folder
~/.kfm/projects/<project>/fleets/<fleet>/  a fleet's folder, as today, with its name
```

`kfm run`, `resume` and `status` name the project and the fleet.

`max_units` stays in `fleet.toml` as a guard against a lead that hires without end; it is
not how a person sizes a fleet.

## Alternatives considered

- **A field for the largest number of agents on the start screen.** What was offered
  first. It answers "how large may it get" with a number and shows nothing of the fleet;
  the person still cannot see what they have.
- **One fleet whose K5 runs the company, with the departments under it.** Needs nothing
  new. But the person is then one agent away from every department, each instruction and
  report passes through a lead that costs a request and loses detail, one limit covers
  everything, and a department cannot be stopped or resumed by itself.
- **Fleets that message each other.** Closer to a company, and deferred: every message
  wakes an agent and costs a request, two agents with an open channel keep answering each
  other, and a lead with requests from its peers has two masters. If carrying things
  across becomes the person's chore, the first step is notes one fleet publishes and
  another reads ([shared team memory](2026-11-12-shared-team-memory.md)), then one
  question with one answer, as an agent asks its supervisor.

## Acceptance criteria

- A project with two named fleets shows both trees on one screen, K5 on top, while both
  run.
- Stopping, resuming and messaging one fleet leaves the other running.
- Closing and reopening the window shows the project with its fleets as they were.
- Switching to another project shows only that project's fleets.
- No number sets a fleet's size in the window.

## Risks

- **Cost.** Several fleets running at once multiply what one costs, and each idle lead
  still checks in.
- **Fleets in one folder** can change each other's files; nothing but the person's
  instructions keeps them apart.
- **A wide chart.** A fleet of dozens does not fit a tree drawn in full; the chart needs
  to fold what is below a rank.
- **The window still runs the fleets**: closing it stops every fleet of the project.
- Fleets kept under `~/.kfm/fleets` are not shown; no conversion is written.
